# r199IQ — neutral table and editor Configuration workspace

This release replaces the mixed navy / warm-gray Configuration presentation from r198IQ with white and neutral gray surfaces, charcoal section headings, and restrained gold selection accents. It removes the duplicate title banner. Workforce populations and expense categories use real tables beside the selected editor; narrower screens stack the table above the editor. Table amounts are authored assumptions, not fabricated calculated costs. The workforce total is read from the latest engine result and explicitly labeled as such.

Workforce defaults and statutory assessments remain accessible in Defaults & assessments. All existing advanced authoring controls remain in their original live DOM nodes, with existing event handlers. Longer guidance is retained in disclosures. Existing inline module presentation is normalized within Configuration, including populated customer acquisition, managed securities, and advanced expense components.

Engagement assumptions and the curve occupy their own Configuration section. On every other tab the same live controls return to the original sidebar, preserving input identity and values. Funding policy remains separate from designated securities books. Engine files and saved configuration schema are unchanged.

## Validation

Chromium tests exercise populated acquisition feeds/channels, managed securities, formula components, tiered components and cost pools at 1600, 1280, 1024 and 768 pixel widths across nine sections. Checks cover no page overflow, neutral panel backgrounds, add/remove/rename/reorder, selected item preservation, explicit compensation Load and unit conversion, draft preservation, relocated sidebar identity, funding edits, keyboard navigation and engagement reset. All pass with no page JavaScript errors.

Existing Chromium paste stability checks, DOM control preservation, authoring state, curve-date and surplus-policy tests, and engine surplus-allocation checks pass. Actual populated screenshots were rendered and visually inspected.

## Deployment

The release is committed to main, as required by deploy_foundry_dynamic.ps1. The ZIP keeps the established SHA/date naming convention and includes RELEASE.json with the expected commit and build stamp. A nested rollback ZIP restores the exact original r198 tracked tree through a forward commit. Extract it to Downloads only when reverting. Saved engagement data is retained. The IQ suffix does not create a separate data store or hosting service.
