The first IQ delivery incorrectly left main at r198 while IQ changes lived only on iq-generation; the dynamic deployment script fetches main and therefore made no change. The corrected delivery advertises its release commit on main. scripts/package_delivery.py refuses to build if main and HEAD differ, and scripts/verify_delivery.py exercises the fetch-main/fast-forward sequence from the deployment log.

## Deployment and rollback

Deploy the outer release ZIP with the existing dynamic deployment script. It contains delivery/foundry-full.bundle and BUILD_STAMP, as before, plus RELEASE.json with expected main SHA.

The source baseline is r198-rollback (b4ee787). Reimporting the original r198 bundle with a fast-forward script will not undo a newer deployment. Instead, the corrected package includes a nested rollback ZIP under rollback/. Extract that ZIP to Downloads **only when rolling back**, then run the same dynamic deployment script. Its main is a new descendant commit whose entire tracked tree exactly matches r198. This needs no forced reset or forced push. Saved engagement data is not rolled back. The IQ label itself does not create a separate hosting service, GitHub repository or data store.

Keep the rollback ZIP nested until needed so an automatic latest-delivery picker does not accidentally select it. After a rollback, further IQ releases must descend from that deployed rollback commit; do not attempt to fast-forward the older IQ head over it.
