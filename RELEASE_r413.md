# r413 — Unified securities inventory with existing contracts preserved

The Investments rail now has one Securities entry listing every simple AFS/HTM book and every managed portfolio sleeve. Rows show name, classification, saved balance method, portfolio, opening balance in $000s and yield/path. Search and classification/method filters are view state only. Empty saved portfolios remain reachable. Editing opens the existing scheduled-book or target-portfolio controls, selects the requested holding and returns to the refreshed inventory. Legacy section identifiers remain reachable for existing navigation. AOCI is a separate shared-settings section.

Add security requires a name, classification and balance method. Scheduled activity creates the existing simple-book schema. Target allocation selects an existing portfolio or explicitly names a new one and creates the existing managed-portfolio/sleeve schema. New portfolios target zero until configured; a first new-portfolio sleeve owns 100% of its zero target. New sleeves added to an existing portfolio own 0% until allocation is deliberately changed, preserving existing holdings. Blank submission, duplicate sibling names, stale configuration, Cancel and Escape do not author entries. Opening an empty securities workspace no longer creates a placeholder AFS book or turns on AOCI sensitivity. Existing explicit turn-off confirmation behavior remains.

No existing holding is converted, merged, removed or reassigned. Original 80/15/5 Treasuries/GSE/CRA allocations, AFS classifications, 0/20/100% risk weights, equity source, prior timing, zero initialization, explicit yields and authored AOCI sensitivity remain byte-for-byte unchanged while browsing. Financial engine and saved data schemas are unchanged. No save endpoint, restoration or persistence code changed.

Compatibility testing exposed pre-existing hidden Configuration render mutations (unrelated CAC/publication IDs and defaults). When Securities is rendered, unrelated assumptions are projected into a transient rendering copy; real securities/balance objects remain attached to their existing handlers. Publication-ID creation is skipped on that read-only projection. Leaving Securities rebuilds the chosen editor against the real configuration, so hidden transient controls are never used for edits. This guards securities browsing without migrating unrelated old data or re-baselining it as an edit.

Validation: browser test uses the real Configuration renderer. Full input JSON is exactly unchanged on first securities render, filtering, AOCI navigation, both legacy edit routes, Cancel/Escape and duplicate rejection. Engine replay of before/after browsing matches income statement, balance sheet and managed-portfolio outputs exactly. The fixture combines scheduled AFS/HTM books with the 80/15/5 AFS portfolio, distinct risk weights, prior equity/zero source treatment, explicit yields and nonzero AOCI sensitivity. Both creation methods, original portfolio preservation, module switching, empty saved config, empty-workspace opening and 1440/1024/768 widths pass. Existing r412 real-renderer cash-target controls, inline JavaScript syntax/balance controls, and seven r411/r412 accounting tests pass. Inventory, modal and selected scheduled-book layout visually inspected. This is not a full-suite pass claim; no financial-engine code changed.
