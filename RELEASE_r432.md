# r432 — Positive monthly increases from linked account counts

Built on r431 (0ce18e3). Transaction streams linked to an Account stream can opt into Linked activity → Positive monthly increase · account count. An explicit Opening source accounts value is required; no opening population is inferred. The control is a compact activity dropdown plus opening-count field, and the trajectory follows the source. The default remains Use source quantity, preserving existing behavior.

The quantity is MAX(0, source month-end count − prior source month-end count). M1 uses the entered opening source count. These are positive net increases, not gross openings or customer acquisition. Declines generate no negative onboarding. Calculations replay the source chain on canonical months; quarterly models sum monthly positive increases and their monthly prices/cost multipliers, rather than differencing quarter endpoints. Stable links work within a product and across fee/deposit/lending product owners. Source streams must have Account basis and supported canonical monthly operands; incompatible sources, missing/negative openings and incompatible shapes fail closed.

Use standard Transaction → Cost per unit for a one-time onboarding charge. The existing independent cost multiplier handles inflation. No formula-cost stream or duplicate Account population is required. The feature does not automatically create or modify engagement streams.

HYS authoring after deployment: add a Transaction stream named HYS onboarding under the HYS deposit product. Browse/source the existing Private HYS Accounts stream using its stable quantity link. Select Positive monthly increase, opening source accounts 0. Revenue per unit 0; Cost per unit 175 dollars; apply the source's inflation multiplier through the existing cost multiplier path. Do not use gross practice acquisition or charge the active HYS book repeatedly. Deposit operations remains an ordinary Account stream with cost per account 5 dollars per month and inflation.

Validation: four integration tests cover hand-computed nonzero openings, declining/recovering account paths, monthly inflation before quarterly summation, cross-owner links/live changes, full public run and monthly/quarterly quantity equivalence, nonmutation and invalid inputs. UI harness checks explicit opt-in, required opening and clean opt-out. Existing Account Activity (33 checks), population composition (6 tests) and deposit count links (5 tests) pass. All inline/generated JavaScript syntax checks pass. Core, template and legacy linked-stream full public outputs remain identical with the feature absent. No real-browser visual check was available.

No rounding or save mechanism changes. ZIP contains delivery/foundry-full.bundle. BUILD_STAMP = foundry-r432-count-increase.
