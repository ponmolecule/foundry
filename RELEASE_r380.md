# Foundry r380 — customer-linked deposit balances

Built on r379 / 2d27591, including the subsequent source-clarification documentation commit 0b84e6e. Packaged; not deployed.

Deposits now offer Customer count × balance per customer as an opt-in balance method. Choose a Customer Acquisition feed, period-end or period-average count, and an entered dollars-per-customer Series. The existing Flat / Growth / Explicit controls are reused. The field explicitly states dollars per customer; ordinary deposit balances remain $000s. The acquisition link stays live as counts and attrition change. Feed renaming preserves the stable source reference.

Monthly observations are resolved before quarterly aggregation: period-end uses the final monthly product; period-average averages monthly products. Existing opening-balance and interest-basis controls keep their meanings. Conflicting roll-forward mechanics and missing/invalid sources or amounts fail validation. Existing methods and saved inputs are not migrated. As with the existing deposit level policies, this is a Profile A feature; Profile B support is unchanged.

Controls remain in the existing Balance section and reuse its collapse/expand layout, live result readouts and schedule editor. No additional source-number panel is added. Engine diagnostics and Calculation Audit expose the count, per-customer amount and resulting deposit balance with their respective units.

Validation: five new regression tests cover the 60-month HSA count/balance recurrence, live acquisition and amount changes, rename stability, opening book, annual amount schedules, quarterly period-end selection and monthly paired average calculations, validation failures, public/audit units, and equivalence to an entered balance schedule. Real Chromium checks cover the actual grouped editor, source/measure changes, raw-dollar entry, mode restoration, rename stability and containment at 1440/1024/768 widths; screenshot inspected. Existing deposit UI and deposit retention calculation checks pass. Eleven deferred-enhancement/inclusion tests pass. Complete public JSON matches the pre-change HEAD for all ten legacy fixtures. JavaScript syntax and git whitespace checks pass.
